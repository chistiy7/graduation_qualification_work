# Фазовый план: новая программа планирования испытательной лаборатории

> **Принцип:** это **новый продукт**, а не доработка Shaft-production-planner.  
> В финальной версии **нет** цеха валов, заготовок, токарных операций, печей, шероховатости, производственной цепочки.  
> Shaft (`Shaft-production-planner-Main`) — только **референс**: как когда-то организовали SFML, три экрана, save/load. Логику и код производства **не переносим**.

**Назначение ПО:** планирование испытаний партии образцов, размещение испытательных стендов на сетке лаборатории, min **K** (гл. 2–3).  
**Термины:** `00_context/glossary.md`. **Матмодель:** `01_chapters/chapter_03.md`.

**Рекомендуемый каталог проекта (новый репозиторий/папка):**  
`lab-test-planner/` (рядом с Shaft или внутри `диплом/`), отдельный `CMakeLists.txt`, имя бинарника `LabPlanner`.

| Можно | Нельзя |
|-------|--------|

| Алгоритм «перебор на сетке» — **переписать** с нуля под K, Ban, Incomp | `optimiser.cpp` копировать и «подкрутить» |
| — | Старый формат сохранения с полями детали/заготовки |

**Критерий чистоты:** в `src/` нет имён `Part`, `Lathe`, `Furnace`, `blank`, `semiproduct`, `production`, `factory` в смысле цеха; только домен лаборатории (`Specimen`, `TestOperation`, `TestStand`, `LabGrid`, …).

## Целевая архитектура (с нуля)

```
lab-test-planner/
├── src/
│   ├── app/              # Window, App, языки, главный цикл экранов
│   ├── domain/           # Specimen, TestOperation, TestStand, LabZone, Batch
│   ├── model/            # Матрицы Req, Cap, Pred; параметры §3.2
│   ├── engine/           # route, layout, metrics (T,C,N,L,η,K), optimizer
│   ├── ui/
│   │   ├── input/        # экран ввода партии и испытаний
│   │   ├── route/        # экран маршрута
│   │   ├── layout/       # экран сетки лаборатории
│   │   └── compare/      # сравнение вариантов 0 / 1
│   └── io/               # JSON save/load, export CSV
├── resources/            # только лаборатория: стенды, зоны, GUI
├── tests/                # эталон §3.6, сценарии гл. 4
└── data/scenarios/       # демо-входы
```

**Три экрана** (та же UX-логика, что у референса, но **новый код**):

1. **Ввод** — партия S, Req(s,o), справочник испытаний, стенды, веса α.
2. **Маршрут** — порядок операций, перенастройки N, T, C, K′.
3. **Лаборатория** — сетка G, размещение E∪Z, L, η, полная K, авто/ручная планировка.

## Фаза 3 — Планировщик маршрута (2 нед.)

**Цель:** новый `engine/route/`, не ProcessPlanner.

- Построение допустимой последовательности по Pred + Req.
- Машина состояний стенда: переналадка / испытание / блокировка.
- Эвристика или перебор порядка для снижения N и K′.
- Базовый порядок = вариант 0; улучшенный = вариант 1.

---

## Фаза 4 — Сетка и оптимизатор планировки (2–3 нед.)

**Цель:** новый `engine/layout/`, не factory/ Shaft.

- Дискретная сетка, шаг ячейки (параметр 2×2–3×3 м).
- Типы клеток: стенд, проход, буфер, запретная, охлаждение, зона персонала.
- `Ban(g)`, `Incomp(v₁,v₂)`, буферы (вибрация, индукция).
- Размещение pos(e), pos(z); расчёт L по маршруту.
- Оптимизатор: перебор/эвристика размещений с min **K** (не «минимум станков»).

## Фаза 6 — Визуализация образца и лаборатории (1–3 нед.)

| Уровень | Реализация |

| Обязательно | 2D-план лаборатории, иконки стендов |
