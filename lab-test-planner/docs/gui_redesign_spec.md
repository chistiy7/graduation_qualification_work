# Спецификация GUI редизайна (Qt 6 Widgets)

Фаза 6 ребилда. Линукс-only, Qt 6 (`Widgets`, `Concurrent`), без QtCharts (свой
рисунок) и без SFML. Страницы проектируются **заново** под мастер ниже; цель
сборки `lab-test-planner-gui` и связка с `lab_core` сохраняются.

## 0. Принципы
- **C — объединяющая нить.** Каждый экран отвечает: откуда взялась себестоимость
  C и каким рычагом её уменьшить (переналадки, площадь, перемещения).
- **Лексика рамки защиты:** «рациональный вариант», «минимизация C». Без
  «оптимально / глобальный оптимум».
- **Единственный результат = рациональная КОМПОНОВКА стендов**, выбранная по
  min C. САПР перебирает размещения (а в режиме мин. площади — и размеры сетки)
  и берёт рациональное. Формулировка: «просмотрено N вариантов размещения →
  выбран рациональный по минимуму C» (`PipelineOutput.layoutEvaluated`).
  Никакого пользовательского «сравнения вариантов по операциям/по образцам»:
  порядок операций — внутренняя деталь маршрута (`PlanResult.orderingNote`),
  максимум одна поясняющая строка.
- Три новизны редизайна, которые GUI ОБЯЗАН визуализировать (иначе они не видны
  комиссии): (1) переналадка на универсальном стенде; (2) DES-перекрытие —
  оператор уходит обслуживать другой стенд, пока идёт автономный прогон;
  (3) проектирование от минимальной необходимой площади.

## 1. Навигация
Одно `QMainWindow`. Мастер из 3 шагов + строка-итог снизу.
```
[ 1. Ввод ] → [ 2. Расчёт… ] → [ 3. Результаты (вкладки) ]
Итоговая строка: C = … руб | T_cycle = … мин | N = … | η = … %
```
- Шаги 1→2→3 линейные; на шаге 3 — `QTabWidget`, свободное переключение.
- Кнопка «Назад к вводу» сбрасывает на шаг 1, сохраняя последний ввод.

## 2. Шаг 1 — «Ввод сценария» (= `lab::ScenarioInput`)
| Поле модели | Виджет | Правило |
|---|---|---|
| `roomAreaM2` | `QDoubleSpinBox` + чекбокс **«Спроектировать от минимума»** | чекбокс вкл → поле disabled, `roomAreaM2 = 0` (режим минимальной площади) |
| `cellSizeM` | `QDoubleSpinBox`, по умолч. 2.0 | в «дополнительно», обычно скрыто |
| `laborRatePerHour` | `QDoubleSpinBox` | > 0 |
| `energyTariffPerKwh` | `QDoubleSpinBox` | > 0 |
| `specimenVolumeM3` | `QDoubleSpinBox` + подсказка `V=π(d/2)²l` | > 0 |
| `groups` | `QTableWidget`: столбцы `кол-во | вид испытания (combo из selectableTestTypes())` | строки добавляются/удаляются; сумма групп = `batchSize` |

- `batchSize` вычисляется как сумма групп (поле только для чтения) или задаётся и
  валидируется на равенство сумме.
- Кнопка **«Рассчитать»** активна при ≥1 корректной группе.
- Поясняющая подсказка: растяжение/кручение/совмещённое идут на ОДИН
  универсальный стенд → «между ними будет переналадка (рычаг C)».
- Валидация — мягкая, прямо в форме (красный хинт у поля), без модальных окон.

## 3. Шаг 2 — «Расчёт»
- Запуск `Pipeline::runFromInput(in, exportFiles=false)` в фоне через
  `QtConcurrent`/`calculation_worker` (не блокировать UI-поток).
- Лента этапов: препроцессор → раскладка (в авто-режиме: «подбор минимальной
  сетки…») → DES-расписание → метрики.
- Ошибки ядра (`std::runtime_error`, напр. «не удалось разместить») показываем
  как сообщение с предложением задать/увеличить площадь.

## 4. Шаг 3 — «Результаты» (вкладки)

### 4.1 Сводка (главная)
- Карточки показателей; **C (руб) — крупно**, затем T_cycle, T_sum, N, L,
  η_avg, узкое место (`VariantMetrics`).
- Плашка **рациональной компоновки**: «просмотрено `layoutEvaluated` вариантов
  размещения, выбран рациональный по min C» + способ (`layoutNote`,
  brute/эвристика).
- Если `autoArea`: плашка **«Площадь спроектирована от минимума: R×C ячеек = …
  м²»**.
- Тонкой строкой: порядок операций (`orderingNote`) — пояснение, не «вариант».

### 4.2 Себестоимость C
- Горизонтальная столбчатая диаграмма статей `CostBreakdown`: подготовка,
  материалы, энергия(работа), труд, **переналадки**, **энергия переналадки**,
  амортизация, транспорт, площадь. Переналадочные статьи подсветить — это рычаг.
- Таблица: статья | руб | % от C. Итог = `cost.total()`.
- Свой `QWidget` с `paintEvent` (без QtCharts).

### 4.3 Диаграмма Ганта (DES) — ключевая вкладка
- Свой `QWidget` (`paintEvent`), источник — `Schedule.phases`
  (`specimenId, operationId, equipmentId, phase, startMin, endMin, operatorBusy`).
- Строки = стенды; ось X = минуты до `makespanMin`.
- Цвета фаз: **Setup / Run (автономный) / Unload**. Прогон визуально отделить.
- Отдельная дорожка **«Оператор»**: занят (Setup/Unload/ход) vs свободен —
  демонстрирует перекрытие (оператор ушёл, пока стенд прогоняет).
- Вертикальная линия `T_cycle = makespan`.
- Тултип по сегменту: образец, операция, фаза, интервал.

### 4.4 Карта компоновки — отдельный paint-виджет
- Заново спроектированный `QWidget` (НЕ переиспользуем `layout_grid_widget`
  Cursor): сетка `Laboratory.cells()` — стенды (id/тип + ориентация), буферы/зоны
  безопасности (X), проходы; разные цвета по `LabCellKind`.
- Подпись стенда + его η. В авто-режиме — итоговая сетка R×C.

### 4.5 Загрузка стендов
- `QTableWidget` по `equipmentStats`: t_test, t_setup, t_busy, t_idle, η,
  E_work, C_energy, C_setup, C_amort. Сорт по η; выделить узкое место.

### 4.6 Маршрут и предупреждения
- Агрегированный маршрут (как в текстовом отчёте `formatAggregatedRoute`).
- `energyWarnings` списком.

## 5. Экспорт
- Кнопки «Сохранить отчёт (txt)» и «CSV» → переиспользовать
  `Postprocessor::exportTextReport` / `exportCsv` (уже есть), запуск с
  `exportFiles=true` или отдельным вызовом по нажатию.

## 6. Привязка к данным ядра
Ввод → `ScenarioInput` → `Pipeline::runFromInput` →
`PipelineOutput{ bundle, result, layoutNote, layoutEvaluated, elapsedMs }`,
`result = PlanResult{ metrics(VariantMetrics), route(TestRoute), efficiency,
orderingNote, energyWarnings }`.

**Единственная доработка ядра ради GUI:** добавить `Schedule schedule` в
`PlanResult` и строить его в `LabOptimiser::plan` для выбранного маршрута —
иначе вкладке Ганта (4.3) неоткуда взять `Schedule.phases`. Доступ к
`autoArea/roomAreaM2/gridRows/gridCols` — пробросить из
`LayoutOptimizationResult` в `PipelineOutput` (сейчас в pipeline берётся только
`note` и `evaluated`).

## 7. Файловая структура (заново)
Сохраняем цель `lab-test-planner-gui`, перепроектируем содержимое:
- `src/qt/main.cpp` — точка входа.
- `src/qt/mainwindow.{hpp,cpp}` — мастер 3 шагов + строка-итог.
- `src/qt/calculation_worker.{hpp,cpp}` — фоновый расчёт (`Pipeline`).
- `src/qt/pages/input_page.{hpp,cpp}` — шаг 1 (заново).
- `src/qt/pages/results_page.{hpp,cpp}` — шаг 3, контейнер вкладок (заново).
- `src/qt/widgets/gantt_widget.{hpp,cpp}` — НОВЫЙ: Гант DES (4.3).
- `src/qt/widgets/cost_bars_widget.{hpp,cpp}` — НОВЫЙ: столбцы C (4.2).
- `src/qt/widgets/layout_map_widget.{hpp,cpp}` — НОВЫЙ: карта компоновки (4.4),
  вместо старого `layout_grid_widget`.
- CMake: обновить список исходников Qt-цели; на Linux `MACOSX_BUNDLE`
  игнорируется (оставить совместимым).

## 8. Порядок реализации
1. Доработка ядра: `Schedule` в `PlanResult` + проброс auto-area в
   `PipelineOutput` (+ тест на наличие расписания). Коммит.
2. Каркас окна-мастера + шаг 1 (ввод, чекбокс авто-площади) + фоновый расчёт.
3. Вкладка «Сводка» + «Себестоимость C».
4. Виджет Ганта (DES) — центральная новизна.
5. Виджет карты компоновки + загрузка стендов + маршрут/предупреждения.
6. Экспорт.
7. Приёмка пользователем (визуальная), правки UI/UX.

Каждый блок — отдельный коммит. Приёмка — с участием пользователя.
