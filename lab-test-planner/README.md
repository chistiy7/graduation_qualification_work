Метрики **T, C, N, L, η** и целевая функция (**C** в руб. или **K**) считаются из данных задачи и построенного маршрута.

## Архитектура

Препроцессор → ядро (`RouteAnalyzer`, `StandStateAnalyzer`, `MetricsEngine`) → постпроцессор → GUI → save/load.

## Сборка и запуск

```bash
./scripts/build.sh
./scripts/run.sh                 # GUI
./scripts/run.sh --cli           # интерактивный ввод: площадь, партия, типы испытаний
./scripts/run.sh --debug demo_simple        # отладочный пресет
./scripts/run.sh --debug demo_two_specimens # отладочный пресет
```

В режиме `--cli` пользователь задаёт площадь помещения (м), размер партии и виды испытаний; программа подбирает стенды, **оптимально размещает их на сетке** и выводит матрицу размещения, минимальную ЦФ и разложение себестоимости по статьям.

## Тесты

```bash
./build/LabPlanner_test
```

Проверяются свойства модели (N, L, C, матрица состояний), не фиксированные числа из §3.6.

## Данные

Вход: `ScenarioBundle` — партия S, операции D, стенды E, сетка G, зоны Z, Req/Cap/Pred, `objectiveMode`, веса α.

Сравниваются две **стратегии упорядочивания** маршрута (варианты 0 и 1).
