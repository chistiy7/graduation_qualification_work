## Архитектура

Препроцессор → ядро (`RouteAnalyzer`, `StandStateAnalyzer`, `MetricsEngine`) → постпроцессор → GUI → save/load.

## Сборка и запуск

```bash
./scripts/build.sh
./scripts/run.sh                 # GUI
./scripts/run.sh --cli           # интерактивный ввод: площадь, партия, группы испытаний
./scripts/run.sh --debug demo_simple        # отладочный пресет
./scripts/run.sh --debug demo_two_specimens # отладочный пресет
```

В режиме `--cli` пользователь задаёт **площадь помещения**, **общее число образцов** и **группы** (N образцов + их типы испытаний). Программа подбирает стенды, **оптимально размещает их на сетке** (с запретной зоной 1 ячейка вокруг каждого стенда) и выводит **один оптимальный план**: карту размещения, минимальную ЦФ и разложение себестоимости по статьям.

## Тесты

```bash
./build/LabPlanner_test
```

Проверяются свойства модели (N, L, C, матрица состояний), не фиксированные числа из §3.6.

## Данные

Вход: `ScenarioBundle` — партия S, операции D, стенды E, сетка G, зоны Z, Req/Cap/Pred; целевая функция — min **C** (руб.).


Результат — **один оптимальный план** (размещение + порядок операций с min C), без сравнения «вариант 0 / вариант 1».
